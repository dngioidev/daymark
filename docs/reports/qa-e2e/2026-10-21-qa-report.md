# QA end-to-end report: v1.1.0 (branch `cycle-5-ux-redesign`, 2026-10-21)

Customer-style testing of every product area: Today, Markdown editor, History, Notes, backup/restore,
settings, multi-tab use, midnight rollover, phone layout, and two-device sync against the real server.
Each probe asserts the **correct** behaviour, so a failing probe is an open bug.

## 1. Baseline (existing suites, all green)

| Check | Result |
|---|---|
| `npm run lint` | exit 0 |
| `npm test` | 70 passed, 1 skipped |
| `npm run build` | built |
| `npm run validate:ai` | all checks passed |
| `npm run test:e2e` (PWA, phone, offline) | 16/16 pass |
| `npm run test:sync` (two devices + restart) | 7/7 pass |

The bugs below are on paths these suites do not cover.

## 2. How the bugs were found

- **Browser probes:** `scripts/e2e-qa-regressions.mjs`. This is the production build plus Chrome via playwright-core.
  It seeds IndexedDB per scenario. To run it: `npm run build && npm run test:qa -- <scenarioPrefix>`.
- **Logic probes:** vitest against `lifecycleEngine`, `markdownEngine`, `merge`, `vaultArchive` (scratch, removed;
  every assertion is carried into the fix plan as a permanent test).
- **Sync probes:** vitest against the real in-process server (`createApp`) using `syncOnce`/`applySyncOutcome`, the same harness as `server/app.test.ts`.

Results: 18 of 31 browser checks failed, 17 of 31 logic probes failed, and 5 of 5 sync probes failed. These collapse into the distinct bugs below (BUG-17 was added after a report from the product owner).
