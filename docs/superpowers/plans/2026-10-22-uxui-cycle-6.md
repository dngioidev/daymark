# Cycle 6 UX/UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the user personalise Daymark and plan ahead, and give screens more room:
- an in-app theme, background photos, synced colours and text size;
- a Calendar that reaches into future days;
- a full-width Today and a full-height Notes;
- a fixed-size Settings dialog that saves instantly;
- styling per Android widget;
- search and keyboard shortcuts.

**Architecture:**
- **Appearance is a new synced `AppSettings.appearance` object.** A pure colour module resolves it into CSS custom properties, and a `useAppearance` hook writes them to `<html>`. Dark mode becomes class-driven.
- **Photos are device-only.** They are Blobs in the existing IndexedDB `kv` store and are kept out of the in-memory cache.
- **Day-level features are pure functions** in `lifecycleEngine.ts` and `taskActions.ts`, wired through `App.tsx`. These are the rollover tombstone fix, move task, and future days.
- **Widget styles live on the native side, per widget id.** A thin configure activity hands off to the WebView UI through the existing bridge-action pattern.

**Tech Stack:**
- Web: React 19, TypeScript, Vite, Tailwind v4, Vitest (node environment; components are tested via `renderToStaticMarkup` or pure helpers).
- Browser suites: Playwright scripts.
- Android: Capacitor 8 with a Glance widget in Kotlin; JVM unit tests run with `npm run android:build -- --test`.

**Spec:** `docs/superpowers/specs/2026-10-22-uxui-cycle-6-design.md`. Read its "Decisions after the builder check" section; it settles most edge cases.

## Global Constraints

- **Tailwind:** use only real Tailwind v4 classes and the stone palette (`stone-50`…`stone-950`). Desktop content keeps `max-w-[1800px]`.
- **Types** live in `src/types/daymark.ts`. Keep the markdown task comment format `<!-- daymark: task_id=<id> status=<status> created=<date> ... -->` unchanged. Rollover must stay idempotent.
- **Dialogs** are real dialogs (`src/components/ui/Dialog.tsx`): focus trap, Esc, inert background, focus return. No `alert()` or `confirm()`.
- **Readability beats decoration.** Every "Automatic" colour must reach a WCAG contrast of at least **4.5:1**. A custom colour below 4.5:1 shows an inline warning but is not blocked.
- **Photo limits:**
  - at most **5** photos;
  - longest side **2560 px**;
  - WebP, or JPEG where WebP isn't available, at quality **0.82**;
  - a thumbnail with longest side **320 px**.
  - Photos never enter sync, export or backup, and the sign-out wipe removes them.
- **What syncs:** the appearance fields (theme, Light/Dark colours, dim, blur, text size) sync inside `settings`. The chosen photo slot, collapsed sections and widget styles do not.
- **No server changes.** No new sync entity keys. No IndexedDB version bump.
- **Shortcuts:**
  - **Ctrl/⌘ K stays the new-task sheet.**
  - Search opens with **Ctrl/⌘ Shift F**, with **/** when no field has focus, or with a header button.
  - `?` opens the cheat sheet; `g t`, `g c` and `g n` go to Today, Calendar and Notes.
  - No shortcut fires while typing in an input, textarea, select or contenteditable.
- **Copy:** plain words, as in cycle 5. Dates use `formatDay` / `formatFullDate`.
- **Commits** are authored as `dngioidev`, and every message ends with `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`.
- **Before marking a task done,** `npm run lint` and `npm test` pass. A task that touches Android also runs `npm run android:build -- --test`. A task that adds browser cases runs `npm run build` and then that suite.

## Review Focus

1. **Upgrade with existing data in dark mode.**
   - A vault created before this version, opened in a system-dark browser, must stay dark.
   - Today's browser suites seed data with `colorScheme: 'dark'` and screenshot dark screens. They must keep producing dark screens. (Task 2 test plus Task 11 suites.)
2. **A settings round-trip through older code paths.**
   - Settings arrive by sync with `appearance` set. A Statuses edit is then saved. `appearance` must survive, and so must an import of a 1.2.0 backup that has no `appearance`. (Task 2 test.)
3. **A very bright or very dark photo with "Automatic" text.**
   - Page titles drawn on the photo must stay at 4.5:1 or better.
   - The dim is raised automatically when needed. (Task 4 tests.)
4. **Moving a task, then the following mornings.**
   - The task appears only on the target day, never in between and never back on the source day.
   - This also holds after Undo, and after a two-device sync. (Task 1 tests plus a Task 11 QA case.)
5. **Settings validation under instant save.**
   - An invalid "Urgent after" value must not be saved and must not throw.
   - Closing the dialog mid-edit keeps the last valid value. (Task 3 test.)
